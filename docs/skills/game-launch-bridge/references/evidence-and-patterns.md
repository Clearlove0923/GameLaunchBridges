# 已有桥接原理与采集模板

以下是选型依据，不是跨游戏通用参数表。采用前阅读对应文档，并核对版本、渠道和实机边界。链接指向仓库内当前维护的实现说明。

## 按问题阅读案例

| 场景 | 参考 | 应复用的判断方法 |
|---|---|---|
| 本体可使用已确认参数启动，目录随版本变化 | [燕云十六声](../../../WhereWindsMeetLaunchBridge.md) | 有限发现本体、官方参数与配置的来源、完整路径跟踪；不复制其参数到其他游戏 |
| 官方子入口比本体更稳定，但会提前退出 | [无限暖暖](../../../InfinityNikkiLaunchBridge.md) | 通过官方子入口建立会话，跟踪真实 Shipping 进程；`-skiplauncher` 仅适用于该链的已验证范围 |
| 参数正确仍缺 SDK 初始化 | [卡拉彼丘](../../../CalabiyauLaunchBridge.md) | 区分启动记录参数与常驻官方宿主；历史默认延时不等于通用的就绪检测 |
| 自动启动能进游戏却缺角色语音 | [异环](../../../NevernessToEvernessLaunchBridge.md) | 对照相同本体/参数/工作目录的启动时序；等待本次资源检查完成后触发原实例 |
| 直接本体启动被认证拒绝 | [终末地](../../../ArknightsEndfieldLaunchBridge.md) | 提权和补参数仍出现 10100；保留官方入口→运行时→游戏链，等待当前会话就绪并触发官方动作 |

异环记录的关键证据是 `/autoplay` 早于资源检查完成且语音缺失；终末地记录的关键证据是 SDK 拒绝直启。两者支持保留官方检查流程，但不能证明内部机制相同，也不能证明终末地仅增加延时即可自行创建本体。

## 每款游戏的证据记录

在对应游戏实现文档中维护以下内容；采集缺失写“未知”，不要补猜测值。

### 基线与对照

| 项目 | 记录内容 |
|---|---|
| 环境 | 日期/时区、游戏/启动器版本、渠道、架构、相关权限、官方图形选项 |
| 起始状态 | 冷启动/热启动、已有实例、已登录/需登录、资源是否更新完成 |
| 官方手动启动 | 入口、脱敏参数、工作目录、进程接力、检查与点击时间线、功能结果 |
| 本体直启 | 调用方法、错误/日志、可操作画面、登录、语音、反作弊、退出结果 |
| 候选桥接方案 | 每次只改变的因素、预期、实际结果、结论边界 |
| Steam | 是否实际通过 Steam 测试、桥接父子实例与在线/时长、退出跟踪结果 |

### 进程与状态时间线

| 时间 | 来源/采样方式 | 会话与进程身份 | 事件 | 脱敏事实 | 局限 |
|---|---|---|---|---|---|

记录快捷方式→入口→运行时→包装入口/反作弊→本体的真实顺序。父子关系和时间相关性不能单独证明认证传递方式；“工作目录读取失败”与“确认该目录”必须区分。

### 参数证据

| 参数 | 发现文件/进程/官方说明 | 适用入口 | 含义是否确认 | 是否动态/敏感 | 对照结果 | 版本/渠道 |
|---|---|---|---|---|---|---|

对页面选择、自动开始、既有实例转发和渲染接口分别记结果。保留非敏感字段的准确拼写，不纠正官方拼写后再测试；一次性认证字段只记存在和脱敏类别，不保存值。

### 最终选型结论

写明：直启是否足够、必须保留哪些官方进程/检查、就绪证据如何绑定当前会话、怎样触发一次开始、怎样确认真实本体及退出、更新哪些部分会失效，以及哪些功能尚未实机验证。
