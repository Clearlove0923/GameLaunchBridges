# 游戏启动桥接器开发

目标是提供稳定的单 EXE 入口，同时保留游戏所需的官方检查、登录、SDK 和反作弊流程，以及可供 Steam 跟踪的真实生命周期。先读仓库根目录及目标游戏下的 AGENTS.md，再读该游戏 README 和实现文档。仓库规则优先；本 Skill 不授权发布、修改官方文件或操作其他游戏。

## 1. 先判断本体能否直接启动

确认游戏、渠道、安装范围、版本，以及用户希望使用的入口。优先检查已有采集证据和实现，避免重复启动。记录现有游戏/启动器的完整路径、PID 与创建时间作为基线，区分已有实例和本次创建实例。

在用户授权的实机范围内先做一次最小直启验证：使用已知的本体路径与合理工作目录，不猜测其他游戏的参数、不自动反复提权重试。保留错误弹窗、退出码和脱敏后的游戏日志。路径、工作目录不确定时先采集，不能把调用错误误判成官方禁止直启。

“可以直启”须有进入可操作画面的实机证据，并注明登录、角色语音/音效、反作弊和正常退出各项是否验证。仅 CreateProcess 成功、进程出现、窗口出现、退出码 0 或自动测试通过都不足以确认。一次登录缓存下成功，也不能证明首次运行和冷启动可用。

- 本体直启正常且覆盖所需场景：采用最小的发现、启动/附着与生命周期桥接。
- 直启失败、依赖启动器已运行，或虽进入游戏但缺语音/功能：先完成 Capture，再编写启动逻辑。
- 已有当前渠道和版本的完整 Capture：复用并补采缺失项，不为满足流程重复制作工具。
- 无实机访问或授权：可以实现 Capture 和固定测试，但明确“直启能力待实机确认”，不臆造结论。

即使最小直启成功，发布前仍核对官方启动方式；需要官方参数或工作目录而证据不足时，也进入采集流程。

## 2. 先制作 Capture，再采集官方启动

Capture 是独立诊断工具，默认 C++20/Win32，源码、构建和测试放在该游戏目录内，不混入其他游戏逻辑；诊断工具不默认成为正式 Release 附件。先证明采集范围和脱敏正确，再让用户通过官方入口手动完成一次正常启动、进入游戏和正常退出。

按需记录以下信息，并为每项标注来源、时间与可信度：

- 采集日期/时区、渠道、启动器与本体版本、冷启动或已有实例、官方图形选项。
- 快捷方式目标、参数、工作目录；协议/注册表入口只读取与本游戏相关项。
- 官方入口到运行时、SDK/反作弊、包装入口和本体的进程接力；PID、父 PID、创建时间、完整路径、架构、权限级别、创建/退出时间及退出码。
- 各关键进程的脱敏命令行和可获得的工作目录；读取受限字段标为未知，不用父目录猜测替代。
- 本次官方日志会话的资源检查、网页加载、登录、可开始状态、点击时刻和游戏创建时刻；必要时记录窗口所属 PID、线程、类名、尺寸和可访问控件。

范围限定为已确认的安装目录、官方日志范围和相关进程链。路径归属使用规范化后的路径组件边界判断，防止相似前缀、跨盘路径、目录联接导致采集无关进程。启动器派生到范围外的反作弊进程可按已确认关系记录身份，不扩展成全盘扫描。父 PID 必须结合创建时间核对，避免 PID 复用误判；轮询可能漏掉短命进程，应记录采样间隔和缺口，必要时采用系统进程事件补采。

Capture 不注入、不伪造父进程、不读取认证内存、不修改官方 EXE/配置、不禁用检查。账号、令牌、Cookie、密码、票据与用户身份在写盘前脱敏；未知参数值默认遮蔽，仅白名单中的非敏感字段保留。不得把原始敏感日志提交到仓库；回归样本使用相对路径、虚构身份和脱敏状态记录。

## 3. 扫描官方参数，并逐项验证

按证据顺序查找：真实快捷方式/进程命令行 → 官方说明与受支持的帮助 → 本游戏启动器的可读配置、日志、脚本或前端资源 → 官方二进制中的参数字符串。

扫描只读且限定文件类型、文件数和安装范围。不要执行枚举出的所有候选参数；`--help` 等看似帮助参数也可能启动程序，执行前评估实际行为。不解密私有认证材料，不把一次性票据固化为配置。需要联网查官方说明时使用官方来源，并记录地址与日期。

维护参数证据表：参数、发现来源、适用入口、作用假设、动态/敏感性、实机结果及版本边界。必须区分：

| 证据 | 可以得出的结论 |
|---|---|
| 字符串或资源中出现 | 仅候选，不能证明支持或含义 |
| 官方进程实际携带 | 确认曾使用，不能证明单独复制就足够 |
| 官方文档说明 | 在说明的版本和范围内有依据，仍核对本机行为 |
| 对照实机验证 | 仅确认已测试的渠道、状态和功能 |

分别验证“打开游戏页面”“触发开始”“转发给已有实例”“保持 SDK 宿主”“选择图形接口”的实际效果。发现 `/autoplay`、`-skiplauncher` 或类似名称，不立即采用；对比资源状态时序、登录与语音。不要把 Steam 尾随命令误当作本体参数，也不要把图形选项名称或着色器重编译现象当作实际渲染接口证据。

## 4. 按证据选择桥接方式

先读 [已有桥接原理与采集模板](references/evidence-and-patterns.md)，只选择相关案例。优先采用已实机确认且依赖最少的方案，不按游戏名称相似性复制参数或路径。

| 条件 | 方案 |
|---|---|
| 本体及必要的非敏感参数足够 | 直接启动本体，跟踪真实进程 |
| 官方子入口可可靠建立上下文 | 调用官方子入口，再跟踪本体，允许入口先退出 |
| 必须保留后台 SDK/渠道宿主 | 保持官方宿主，按当前游戏证据触发包装入口或官方动作 |
| 必须完成资源/网页/登录检查 | 等待本次会话就绪，再触发同一官方实例的“开始游戏” |
| 尚无可信自动触发或就绪依据 | 保留可见的官方手动操作，记录缺口，不以猜测拼出自动化 |

“等待检查完成”和“由谁创建本体”分别验证。终末地式认证失败不能推导成等待几秒后自行创建本体就可通过；相同命令行也不能证明 SDK 上下文相同。

需要等待时，使用当前 PID/创建时间、会话、线程或游戏 UUID 绑定的最新状态，拒绝旧日志、旧状态和其他游戏误命中。官方检查可以重复或回退：登录、更新、下载、维护、阻挡弹窗或新会话应使旧就绪失效。状态等待必须有超时和可诊断错误，不用固定休眠宣称检查完成。若既有实现只能延时初始化，文档明确该局限，后续优先寻找真实就绪证据。

触发优先使用经确认的官方接口或可访问控件，其次才是经实测的窗口消息/比例坐标。触发前重新核对进程完整路径、窗口所属、版本/布局及最新就绪状态；单次触发后等待新本体，禁止循环盲点。坐标、隐藏窗口消息和版本前缀属于该游戏的兼容边界。需要用户登录、更新或手动处理时恢复官方窗口。

失败按阶段定位：路径发现 → 官方入口/权限 → 会话与检查 → 开始动作 → 本体创建 → SDK/登录/反作弊 → 游戏功能 → 退出清理。依据日志最早的异常阶段修正，不能只看到游戏未启动就归因于路径或权限。

## 5. 落地实现和回归

遵守 AGENTS.md 的语言、单文件、图标、目录、配置、日志和版本规则。采用有限安装范围发现、可排除递归和可配置候选/深度；不写死个人盘符和版本层级。标准版、精简版、渠道差异和更新目录用固定样本覆盖。

Steam 尾随命令与桥接器选项隔离，不把未知载荷转发给本体。附着与跟踪同时检查进程名和完整路径，保留句柄观察退出码；用可配置防抖处理进程接力/重启。普通实例提权后要等待子实例，避免 Steam 过早结束跟踪。

仅隐藏和清理已核对身份且属于本次任务的启动器窗口/进程；保留必要宿主到游戏结束。先正常关闭，强制结束前复核进程身份、游戏是否重启和是否承载其他任务；不杀游戏、反作弊或整个进程树。

正常和错误流程写入 EXE 同级的唯一主要日志，按条目保留七天，长时间运行定期清理；记录阶段、运行 ID、PID、版本、有效非敏感配置、路径、命令/工作目录、状态转换、退出码、时长与异常堆栈。脱敏规则同时用于参数、错误和 Capture；写入失败的弹窗显示具体原因。

按变更范围完成验证：

- 实现变更：Release x64 编译、单文件/依赖、图标、路径发现、日志位置、精确七天保留和错误堆栈。
- Capture/状态/触发变更：范围限制与脱敏、旧会话拒绝、最新状态回退、更新/登录阻挡、超时、同名异路径、进程接力和退出防抖的固定回归。
- 实机：官方手动基线与桥接对照，记录冷/热启动、登录、语音、图形选项、UAC、反作弊、游戏退出和启动器清理；Steam 实际在线/时长另行验证。
- 仅修改 Skill/文档：验证 frontmatter、相对链接、流程完整性和差异，不以未运行的 EXE 测试作为通过结论。

自动测试和模拟进程只能证明自动化逻辑，不能代替真实游戏功能、认证和 Steam 结论。无法实机验证时交付可执行的采集/验证步骤和明确边界。

## 6. 文档和交付

同步游戏 README、`docs/<英文游戏名>LaunchBridge.md` 和必要的根 README。实现文档包含为什么需要桥接器、带日期/渠道的官方流程、桥接原理、配置日志、更新边界、自动与实机范围，以及源码/配置/固定测试入口。将“实机采集确认”“自动测试确认”“推断或未验证”分别表述。

交付说明采用的启动方式、关键证据、失败原因与仍待确认项。仅在用户要求推送或发布时执行相应步骤；上传文档不等于发布 EXE。提交仅包含本次任务内容，保留其他工作区改动。推送前更新 PUSH_HISTORY（最近五次），将同一提交推送 origin/cnb 并核对远程 SHA；有分歧停止普通推送，不强推。版本发布另按仓库规则同步双端标签、Release、同一附件哈希和官网，任何未完成项如实报告。
