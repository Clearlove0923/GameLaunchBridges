# Arknights Endfield LaunchBridge v1.0 实现原理

当前实现为 C++20 原生 Windows x64，静态 MSVC 运行库、单文件。2026-10-15 已完成构建、自动检查，用户已实机确认 C++ 版本启动正常。正式版本 v1.0（[GitHub](https://github.com/Clearlove0923/GameLaunchBridges/releases/tag/ArknightsEndfield-v1.0) / [CNB](https://cnb.cool/SteamCN-GameLauncher/GameLaunchBridges/-/releases/tag/ArknightsEndfield-v1.0)）。历史原型验证与当前 C++ 实机结论分开记录。

## 为什么需要桥接器

实机采集确认：直接运行 Endfield.exe，即使提权并带上观察到的参数，仍可能被官方 SDK 拒绝，Player.log 出现 `PC launch auth failed, errorCode: 10100`，并要求从官方启动器启动。仅创建本体进程、退出码为 0，均不等于进入可操作游戏画面。

官方入口负责登录、SDK、资源检查和游戏创建上下文；已发现的参数只打开终末地页面，没有确认可直接自动开始游戏的官方命令行参数。Steam 只启动官方入口也不能据此可靠跟踪本体整个生命周期。桥接器维持自身进程，调用真实官方入口、等待官方检查、触发官方按钮并跟踪本体，不伪造父进程、认证信息或 Steam 状态。

## 已确认的官方启动流程

采集日期：2026-10-15；渠道：本机中国大陆鹰角 PC 启动器、终末地，官方运行时版本 1.6.0.1604。安装目录的真实绝对路径不写入源码或示例。

- 官方桌面快捷方式入口：`Hypergryph Launcher/Launcher.exe --game=endfield --reason=4`，工作目录为 Launcher.exe 所在目录。
- 入口接力到版本目录中的 Games.exe；版本目录名不是固定定位依据。普通入口观察到 `--reason=0`；认证失败重定向协议观察到 `--reason=6`，后者不等于可自动启动。
- Games.exe 完成页面、登录/SDK 与资源状态检查，再创建游戏 Endfield.exe。观察到默认游戏参数 `-launcher_lang=zh-cn -launcher_sub_channel=1`；勾选官方 DX11 时附加 `-force-d3d11`，对应样本日志明确显示 Direct3D11。
- 未勾选 DX11 时只称“官方默认模式”，不将重新编译着色器或用户选项名称单独当作 DX12 证据。桥接器不管理图形接口或游戏参数。
- 反作弊/登录上下文由官方链负责，桥接器不修改官方 EXE、配置或反作弊组件。已有观察不能证明所有渠道、登录/语音或反作弊场景通用。

官方就绪日志位于 LocalLow/Hypergryph 下有限目录中的 `logs/games.log`。按已核对运行时窗口的 UI 线程筛选，从最新 `csc PrintConfig` 中匹配 endfield 和 UUID；只接受此会话/UUID 最新 `OnMainBtnStateInfoChanged`。状态必须为 `start_game`，且查询已完成、无需登录/购买、服务未停用、未处于准备启动。隐藏模式额外要求本会话的 `OnJsBridgeConnected` 与 `OnRecvWebPageLoaded`。进入新会话即清除旧状态。

## 桥接器原理

### 有限路径发现与身份

从桥接 EXE 所在目录和有限上级目录递归发现，可回退至鹰角卸载项指示的安装范围；显式 `--install-root` 可缩小范围，拒绝驱动器根目录。不进行无边界全盘扫描。默认搜索深度 8、最多 10000 目录，跳过目录联接/符号链接和排除目录。候选优先级可配置，多个不明确候选会报错。

从游戏附近最多三个有限上级范围寻找 Launcher.exe，以官方产品属性确认，优先较近目录，同优先级冲突报错。运行时按启动器目录内的 Games.exe 完整路径与 Qt 主窗口匹配，不写死 1.6.0 目录。游戏附着同时核对文件名与完整路径，保留进程句柄观察退出码，排除其他目录同名进程。

### 官方触发与窗口

原始桥接实例通过 runas 提权启动自身并等待子实例退出；提权后使用每安装范围互斥锁避免重复启动。先启动窗口管理线程，再调用真实官方入口，保留官方 SDK/检查流程。每 20ms 检查并隐藏已核对路径的 Qt 主窗口，保留真实官方托盘，不处理 UAC 窗口；短暂首帧闪现仍可能发生。

根据当前线程/UUID 就绪状态等待，而非固定休眠后盲目点击。触发前重新确认进程路径、UI 文件版本前缀（默认 1.6.）、客户区尺寸与比例、阻挡弹窗及最新状态；按本机实测相对坐标 0.835/0.866 发送一次窗口按钮消息。隐藏模式不要求前台或采样其他桌面窗口；可见诊断模式要求前台及按钮黄色像素。需要登录、下载、更新或出现错误时恢复官方窗口并停止自动操作。C++ 版本启动已由用户实机确认正常；其他 UI 布局仍需分别验证。

### Steam 尾随与退出

只解析桥接器自身的根目录、配置和验证选项，Steam 尾随命令隔离，不转发给官方启动器或本体。官方入口参数来自受控默认值或用户 INI；不将未知参数原文写日志。

游戏消失后默认防抖 10 秒，期间同路径重启会继续跟踪。随后向已绑定的官方 Games 窗口发送 WM_CLOSE；5 秒后仍驻托盘时重新确认保留句柄仍存活、PID 完整路径一致、游戏没有重启、没有启动器目录外的直接子进程，才可结束对应 Games 进程。未知子进程路径视为其他任务，跳过强制退出。不终止进程树、游戏或 ACE。此直接子进程保护不能证明所有官方未来进程结构，需更新后复查。

## 配置与日志

[示例 INI](../ArknightsEndfield/examples/ArknightsEndfieldLaunchBridge.ini) 是可选配置，同级默认文件名为 `ArknightsEndfieldLaunchBridge.ini`，亦可通过 `--config` 指定。旧原型 JSON 不兼容。覆盖本体/入口/运行时名称、产品属性、候选优先级、排除项、深度、官方参数、游戏代码、UI 版本/坐标、窗口和退出策略、超时/防抖。中文使用 UTF-16 LE BOM；示例不含用户绝对路径。

唯一主要日志为 EXE 同级 `ArknightsEndfieldLaunchBridge-log/ArknightsEndfieldLaunchBridge.log`。包含 ISO 8601 时区时间、运行标识和 PID、版本/Windows 构建/进程架构、生效路径与候选、实际官方入口及工作目录、状态转换、隐藏/触发、游戏出现/消失/退出码、启动器关闭结果、退出防抖和总运行时长。错误包含异常类型、消息与原生调用堆栈；BridgeError 在构造时捕获堆栈。日志初始化/写入失败弹窗显示原因。

启动时以及运行中每小时按含时区时间戳清除超过七天的记录，不生成每日或每次运行的新文件。线程锁和进程间互斥锁保护提权前后实例写入。官方日志原文、账号/令牌/密码/Cookie、自定义参数值和未知尾随内容不转写；因此自定义入口参数仅记录已脱敏提示。错误 10100 检测是失败提示，不作为成功判断。

## 更新失效边界

官方版本更新后应重新采集入口、参数、工作目录、进程接力、资源状态、登录/反作弊上下文和 UI 布局。普通目录变化由有限发现适配；UI 版本前缀、按钮坐标或日志格式改变则可能明确拒绝或超时，须实机复核后更新配置/实现并增加固定样本。默认仅针对本机 1.6.x UI 观察设计，不能宣称其他语言、主题、缩放、渠道或版本通用。

## 自动测试与实机验证边界

2026-10-15 自动确认：Release x64 编译；47 项原生回归覆盖当前会话/线程/UUID、网页就绪、登录标记、认证失败、参数隔离/引用、UI 版本/像素判定、标准/精简/变动版本目录、深度/排除/优先级/冲突、官方产品属性、全路径附着、同名异路径排除、模拟进程退出码和防抖、日志位置与堆栈。产物检查另外覆盖单 EXE、仅 Windows 系统 DLL、版本、官方多尺寸图标一致性、INI、Steam 尾随、精确七天日志保留和发布程序错误堆栈。测试只运行仓库内模拟程序。另对本机真实安装范围执行了 --validate，只读路径与官方入口属性验证通过，未启动真实游戏。

历史 C# 原型实机确认：用户通过官方默认图形设置进入可操作画面并游玩暂未发现问题；随后确认只保留官方托盘且游戏正常打开，正常退出后桥接记录显示游戏退出、防抖、WM_CLOSE 和托盘超时后结束 Games。该过程中官方 PlatformProcess 出现退出异常码，原因/影响尚未确认。历史 Capture 存在跨盘范围判断可能额外记录无关进程的问题，旧工具源码已移除，不随正式桥接器提交。

**当前 C++ v1.0 实机确认**：用户在手动验证后报告“实际启动没有问题”，据此确认本机桥接启动正常。该反馈没有单独覆盖首次冷启动、托盘与退出清理逐项复测；这些功能的完整历史记录来自原型。Steam 在线状态/时长、声音/语音和其他渠道未完成验证。自动测试不能替代这些结论。
